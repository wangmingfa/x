# x 稳定契约 · Contract v1

本文件是 `x` 对脚本与自动化调用方的显式契约：退出码、输出格式与破坏性
操作的确认行为。契约版本 `1`（`x --version-info` 的 `contract` 字段）。

**稳定性承诺**：已发布的契约版本内，本文件的任何条目不发生不兼容变更——
退出码含义不改变，JSON 文档的字段只增不删不改名，新命令遵守同样的规则。
需要破坏性调整时升级契约版本并在本文件记录差异。契约矩阵测试
（`crates/x-cli/tests/contract.rs`）把破坏性操作的行为钉死。

## 退出码

| 码 | 含义 | 触发示例 |
|----|------|----------|
| 0 | 成功 | 一般命令完成；`--dry-run` 打印计划后 |
| 1 | 一般错误 / 系统错误 | 平台调用失败、意外内部状态；`port check` 端口空闲 |
| 2 | — | 保留（clap 参数解析错误不走本表） |
| 3 | 未找到 | `x ps kill 99999` |
| 4 | 权限不足（附 `hint:` 行） | 读受保护资源被拒 |
| 5 | 参数错误 | 非法端口号、未知枚举值 |
| 6 | 超时 | 传输超时（`x net diag`：curl 错误码 28）；`x net top` 的抓包轮不产生此码，读不满窗口时如实输出已有数据 |
| 7 | 能力不支持 | 平台没有该能力（`x bluetooth` 无适配器等） |
| 8 | 状态错误 | 目标处于不可能完成操作的状态 |
| 130 | 用户拒绝确认 | 破坏性操作在确认时答“否” |

约定：

- 拒绝确认（130）是**流程控制**，不是输入错误——脚本可以据此走
  交互回退路径；错误输出一律带 `error:` 前缀与可读消息，权限错误另附
  `hint:` 提权建议行。
- `port check` 特例：0 = 端口被占用，3 = 端口空闲（与“未找到”共用）。
- `bench --check` 特例：0 = 所有目标在预算内，1 = 有目标超预算（与“一般
  错误”共用；JSON 模式仍只输出一个文档，`status` 字段说明是哪个目标）。

## 破坏性操作确认契约

所有破坏性命令（kill、服务 stop/restart/disable、防火墙写入、文件突变、
power、schedule、mount、startup、hosts 写入、bluetooth/window 动词等）
行为一致：

1. **`--dry-run` 恒最先**：打印将执行的计划、退出 0、**绝不提问**。
   管道下也一样——dry-run 是关于未来的问题，不是需要确认的动作。
2. **JSON 不豁免确认**：输出格式与是否突变正交。JSON 模式下忘了
   `--yes` 的脚本会被拒绝而不是静默执行。
3. **`--yes` 跳过提问**，每命令一个 `--yes`（非全局）。
4. **拒绝一律退出 130**，且输出一份 aborted 文档（见下）。

## 输出格式

`--json`（单文档）、`--jsonl`（每行一个文档）、`--csv`、`--plain`
（制表符、无表头）、默认人类可读表格。稳定契约只覆盖 JSON 文档：

- 结构化输出的字段名不随平台变化；平台没有的信息为 `null`
  （“工具没说”），不进行有损假统一。
- dry-run 在 JSON 模式输出**单个文档**：
  `{"dry_run": true, "would": "<计划描述>"}`
- 确认被拒在 JSON 模式输出**单个文档**：
  `{"aborted": true, "would": "<计划描述>", …}`（service 等另附目标字段）
- 表格/纯文本输出不是契约的一部分，可为可读性随时调整列与措辞。

## 自省

- `x --version-info` → `{"x": "<包版本>", "contract": 1,
  "platform": "<平台名>"}`；`contract` 字段与本文件标题的版本一致。
- 配置文件（`~/.config/x/config.toml`）中的非法值**报 warning 并跳过**，
  不让命令失败——配置错误不进入退出码契约。
