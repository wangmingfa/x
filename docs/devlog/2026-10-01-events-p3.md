# 2026-10-01 P3：事件域 `x events`

## 目标

P3 最后一块数据域：把「进程启停 / 网络连接 / USB 插拔 / 磁盘挂载 /
服务状态变化」变成一条可跟踪的差异流，CLI 先落地，为 TUI 实时页留接口。

## 关键决策

### 快照对拍，不是内核订阅

x-core 的信条是「Snapshot, never watch」：trait 只暴露快照读，且
x-core 零平台 cfg（有架构守卫测试钉着）。事件天然像「订阅」，但我们
没有选择 ETW / inotify / D-Bus / FSEvents 这类平台事件源——那会把
五个平台的适配复杂度翻倍，还要在 core 里塞 cfg。

选择：**x-core 每次采样调各管理器取一份快照，和上一轮做差**。
`SystemSnapshot::sample(context, &[EventType])` + 自由函数
`diff(previous, current) -> Vec<SystemEvent>`。轮询循环留在前端
（CLI 现在，TUI 以后），core 只做纯函数。五个家族都走既有 manager
trait，组合根零改动。

### 失败语义：基线重置，不造假事件

`sample` 永不整批失败：每家族独立 `Result`，失败记入
`failures: Vec<(EventType, String)>`，该家族本轮槽位为 `None`。
`diff` 只对「两侧都有 Some」的家族比较——一侧是 None（本轮读失败或
上轮没采）就跳过，下一轮以新的成功快照为基线。

这条规则是刻意的：连接表权限不足时如果拿「空」当结果对拍，会渲染出
上百行「- closed」假事件潮，恢复时再来一波「+ opened」。宁可这轮什么都
不说，如实打 `! 家族 采样失败: 原因`。

### USB 缺省关闭（实测数据）

Windows 侧设备枚举要 shell 出 `Get-PnpDevice -PresentOnly`，本机实测
每次约 1.6 秒（P3 设备域同源）。轮询 2 秒间隔里塞 1.6 秒的子进程不可
接受，所以 `EventType::DEFAULT = [Process, Connection, Mount, Service]`，
usb 需显式 `--types usb` 或 `all`。`--types` 帮助文本里写明原因。

### 差异算法的形状

- 进程 / 连接 / USB / 挂载：按稳定键（pid / path 或 endpoint / 平台 id /
  挂载点）排序后双指针 `diff_sorted`。泛型签名带 `cmp: impl Fn(&T, &T)
  -> Ordering` 和 `emit: impl Fn(EventOp, &T) -> SystemEvent` 两个闭包，
  而不是让闭包返回键——键返回会让借用逃出闭包作用域，编译器不放行。
- 服务另写 `diff_services`：状态迁移需要同时看前后两份记录才能组出
  `~ name: running -> stopped`，双指针只给单侧。
- 挂载点换设备是「- 一个 + 一个」：键是挂载点，同点新设备算 Removed
  + Added，不做「~ 变了」的糊弄（换盘和改文件系统是两回事）。
- USB 键在平台 id，名字只是展示——同型号两个设备靠 id 区分。

### 事件行文本

`+`/`-`/`~` 前缀 + 人话摘要，如
`- stopped worker (pid 2)`、
`+ opened tcp 127.0.0.1:5432 -> 127.0.0.1:52100 [established] (postgres, pid 42)`、
`~ sshd: running -> stopped`。监听 socket 没有对端，摘要省略 `-> 对端`
段。JSON 里 `type`（rename）标明家族，pid / detail 等可选字段
`skip_serializing_if`，未知道具不出场。

### 测试中的「世界变化」

watch 型测试要证明「两轮之间世界变了」，给 `StubProcess` 加了
`set_rows(&self, rows)`——stub 内部本来就有 `Mutex<Vec<ProcessInfo>>`，
只是此前没有写入口。CLI 集成测试起一个线程：`sleep 60ms` 后把进程表
换掉，主线程 `--interval 0.15 --count 3` 跑三轮，断言恰好各出现一次
`- stopped worker (pid 2)` 与 `+ started builder (pid 3)`。间隔与
变异时点留了 2.5 倍余量防抖动。

## 交付物

- `x-core/src/events.rs`（新）：`EventType` / `EventOp` / `SystemEvent` /
  `SystemSnapshot` + `diff`，12 个单元测试（含失败家族不造假、监听
  socket 无箭头、同点换盘 = 删 + 增、序列化只含已知字段）。
- `x-core/src/testing.rs`：`StubProcess::set_rows`。
- `x-cli/src/commands/events.rs`（新）：`x events [--interval 2.0]
  [--count N] [--types LIST]`，文本基线行 + 差异行 + 失败行；JSON 每轮
  一份文档且仅在有事发生时输出。
- `x-cli/tests/cli.rs`：6 个端到端测试。
- README：事件小节 + P3 勾选。

## 验证

- `cargo fmt` → 全仓；`scripts/check.sh` → EXIT=0（295 测试全绿，其中
  events 18 个：12 core + 6 CLI）。
- 跨目标 clippy：`x86_64-unknown-linux-gnu` 与 `aarch64-apple-darwin`
  均 `-D warnings` 通过。
- 本机活体：
  - 基线：`x events --count 1` → `watching process 202, connection 129,
    mount 3, service 279`（无 usb，符合缺省）。
  - 过程：`x events --types process --interval 1.5 --count 4` 期间跑
    `ping -n 4`，实收 `+ started PING.EXE (pid 12596)` 与
    `- stopped PING.EXE (pid 12596)`，另夹带 bash.exe 启停——对拍无漏。
  - USB 显式开启：`--types usb --count 1` → `watching usb 7`，约 1.6s。
  - `--types mount,service --count 2 --json` 无事发生 → 零输出，实测
    符合「静默」约定。
  - `--types flurb` → exit 5 + `unknown event type "flurb"; valid: …`。
