# 2026-10-01 · P3 TUI 增强（七页侧边栏 + 命令面板 + 全局搜索）

把 `x tui` 从四个页签重写成七页侧边栏：Dashboard、Ports、Processes、
Network、Services、System、Disks。数字 `1`–`7` 直达页面，`Ctrl+P`
命令面板，`/` 全局搜索，进程页树形 + 折叠，端口/进程详情与 kill
计划，Disks 页带启动目录用量树。`App` 仍是纯状态机（不碰终端），
`ui.rs` 只画，`event.rs` 只收键。

## 决策

**状态机与绘制分离到「可断言」程度。** `app.rs` 的每个键行为都是纯
转移：`on_key` 返回 `Option<Action>`（如 `Quit`），刷新由 `App` 持
`Context` 拉数据。渲染测试因此不需要终端——`ui/tests.rs` 用
`ratatui::backend::TestBackend` 把整帧画进内存缓冲，逐格取
`buffer.cell((x, y))` 拼回文本做整屏断言（`> 7 disks`、`│> node_`、
`12.5%`）。`app/tests.rs` 是 `app.rs` 的子模块（`pub(crate)` 字段
直接可见），32 个测试覆盖键位转移；共 45 个测试全绿。

**测试不碰真实工作目录。** 用量树默认扫启动目录，测试里用
`#[cfg(test)] set_usage_fixture` 注入假树，避免每次 `cargo test`
都去 walk 仓库；渲染测试同样经它注入 fixture。

**只刷可见页。** 每次 tick 只调当前页的能力（`View::kind()` 决定拉
什么），搜索缓存命中家族时不再重复探测。切换页面立即刷一次，
失败时保留旧行、错误写状态栏——七页各自独立，「socket 表挂了」
不该把进程页也清空（有测试钉住：dashboard 某卡片失败不影响其它
卡片）。

**搜索是「跳转 + 过滤」而不是新页面。** `/` 对进程 / 端口 / 服务 /
网络连接 / 用量树做子串匹配，家族采样失败时在结果里就地注明
（`! processes unreadable`）而不是当作零命中；回车跳到对应页并把
查询词写进该页过滤框，Esc 清除。`p` 是跨页签联动的窄版：选中进程
直接跳 Ports 并过滤它持有的端口。

**kill 走既有计划确认。** TUI 里的 `k`（端口/进程详情里）复用
x-core 的 kill 计划模型，确认框把计划原文摆出来（`terminate 1
process(es) to free this port`），确认后仍经审计装饰器留痕；TUI 只
渲染计划，不自己拼命令。

## 坑

**crossterm 0.29 的 Esc 只认 VK_ESCAPE。** 活体验证用控制台注入
按键时，`UnicodeChar=0x1B` 而 `wVirtualKeyCode=0` 的 KEY_EVENT 被
crossterm 忽略（parse.rs 里 Esc 分支要求 `VK_ESCAPE`），表现为
「Esc 关不掉面板、后续 q 也不退出」。注入端补
`wVirtualKeyCode=0x1B` 后一切正常。

**PowerShell 5.1 的 P/Invoke 三个坑。** ①`$null` 字符串实参被封送
成 `""` 而非 NULL，`CreateProcessW` 的 `lpApplicationName` 因此
`ERROR_PATH_NOT_FOUND(3)`——要显式传 `[NullString]::Value`；
②`0xC0000000` 字面量按 Int32 解析成负数，`CREATE_NEW_CONSOLE`
组合要用十进制 `3221225472`；③`[short]` 加速器不存在（某些宿主），
P/Invoke 签名写 `[int16]`。

**winpty 拖不动 TUI。** `winpty x.exe tui` 报 "stdin is not a tty"
（`-Xallow-non-tty` 又触发 winpty 自己的 `cols > 0 && rows > 0`
断言）。改用 PowerShell 控制台抓屏：`CreateProcessW` 起
`CREATE_NEW_CONSOLE` 隐藏窗口 → `AttachConsole` → `CONOUT$` 读
`ReadConsoleOutputCharacterW`、`CONIN$` 写 `WriteConsoleInputW`，
逐屏注入按键并抓 80×N 文本。TUI 实机验证因此不依赖任何第三方终端。

**渲染断言要注意框线。** 对话行尾是 `│`、侧边栏与正文共享同一行，
`"> serv_\ngo to services"` 这种跨行整段匹配必然失败——改断
`"│> node_"`、`"go to services"` 分别断言。协议名经
`Protocol::name()` 是小写（`tcp`），测试里别写 `TCP`。

## 验证

- 单测 45：app 32（键位转移、每个页面各自刷新对应能力、搜索五种
  家族、树折叠深度、排序轮换、详情 kill 流、面板过滤）+ palette 2
  + 渲染 11（逐页正文、对话框内容、折叠前后、侧边栏高亮）。
- 三 target 交叉 clippy 全绿；`scripts/check.sh` Format / Clippy /
  Test 全绿。
- 本机活体（控制台抓屏，只读操作）：真实 Dashboard（Windows 11
  Pro、host wmf、i5-9400F、CPU 8.6%、内存 33.2%，端口 23/39/103、
  C:\ D:\ E: 文件系统表）；端口页含持有进程与用户；socket 详情 +
  Esc 关闭；`/` 搜索命中进程/端口/服务家族；进程树真实父子缩进；
  服务页中文显示名；Disks 用量树；Ctrl+P 十五个命令并可过滤；
  `q` 退出码 0。TUI 与 `x ps list --limit 8` 的 cpu%/mem/顺序一致
  （共用同一模型），确认零值差异来自适配器采样而非 TUI。
