# 2026-10-01 · P3 显示域（三平台）

新增 `x display list` / `x display info <序号或名称>`。核心模型
`x-core/src/display.rs`，适配器：Windows 走 `windows/display.rs` 的
Gdi32 原生枚举，Linux/macOS 走 `common/display_os.rs`。

## 决策

**Windows 不用 WMI 投影，走 Gdi32。** `Win32_VideoController` 的
`CurrentHorizontalResolution` 是每 GPU 一行的投影，无法与具体监视器
一一对应——多显示器/多 GPU 机器上要靠序号或名称猜配对，违反"保守
归一化"。原生路径每个事实都有确切归属：`EnumDisplayDevicesW` 双层
枚举（适配器 → 挂载的监视器）、`EnumDisplaySettingsW(ENUM_CURRENT_
SETTINGS)` 取当前模式的 `dmPelsWidth/Height`、`dmDisplayFrequency` 与
`dmPosition`（桌面坐标，负值即左副屏）、`GetDpiForMonitor(最近点)`
取有效 DPI 换算成百分比。安全注意点：`DEVMODEW` 的 `dmPosition` 藏在
匿名 union（`Anonymous1.Anonymous2`），`DISPLAY_DEVICEW` 的字段名是
`StateFlags` 不是 `State`；`PCWSTR` 是裸指针别名没有构造器。

**Windows 位置用 `dmPosition` 而不是 `EnumDisplayMonitors` 回调。**
两者都拿得到坐标，但回调版本要 `extern "system"` + raw 指针穿栈，
而 `ENUM_CURRENT_SETTINGS` 本来就填 `dmPosition`，少一层 unsafe。

**Linux 的 sysfs 只答它知道的问题。** `status` 判连接、`modes` 首行
`1920x1080 60.00 …` 拆分辨率与刷新率（第二列是模式的 vrefresh）、
`card0-HDMI-A-1` 去掉卡号即连接器名。位置/主屏/缩放在合成器手里
（Wayland 连问都问不了），sysfs 没有就留 `None`，表格显示 `-`。

**macOS Retina 缩放用「as」换算。** `spdisplays_resolution` 形如
`3840 x 2160 (as 1920 x 1080)`：第一个 `W x H` 是像素分辨率，` as `
之后的第二个是 UI 尺寸，缩放百分比 = 像素宽 ÷ UI 宽。`spdisplays_
pixels` 存在时优先用它当原生分辨率。`spdisplays_main` 只有
`…yes/…no` 才映射布尔。`size_at` 扫描器同时接受 `1920 x 1080` 和
`1920x1080` 两种间距，逗号括号类文本一律忽略。

**info 的选取规则。** 数字按 1-based 行号（0 报 InvalidInput、
越界报 NotFound 3）；名称先精确匹配（忽略大小写）、再子串匹配，
子串命中多个时报 InvalidInput 并把候选全列出来——歧义不替用户选。

**HDR 本轮不做。** Windows 需要再过一遍 `QueryDisplayConfig`
（`DISPLAYCONFIG_GET_ADVANCED_COLOR_INFO`，结构体带 union，单独一轮），
macOS/Linux 的读取口径不一；README 的 P3 行如实标注未提供，不勾掉
这句话而装作做了。

## 验证

- 单测：core 2（JSON 缺席、往返）、platform 4 cfg 门控（连接器名、
  modes 解析、macOS 双布局、size 扫描器）、CLI 5（破折号行、JSON
  缺席、序号与名称选取、歧义/越界/零，无能力 7）。
- 三 target 交叉 clippy 全绿（当晚跑）。
- 本机活体：`x display list` → 1920x1080 / 60 / 100% / yes / (0,0)，
  JSON 全字段；`display info 1` 与 `info Generic` 同结果；`info 9`
  退出 3；`display info Monitor`-类歧义用例由单测覆盖。
