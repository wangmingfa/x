# 2026-10-01 证书与网络诊断（x cert / x tls / x http / x net check）：不带 TLS 栈的走法

## 分层：探测交给平台工具，x 只做结构化与归因

工作区里没有 HTTP/TLS 依赖，也不打算为此引一个——layer-3 的既定做法是驱动
平台自带工具：HTTP 三平台统一 `curl`（Windows 10+ 自带）；TLS 在类 Unix 走
`openssl s_client` + `x509`，Windows 走 PowerShell `SslStream` +
`X509Chain`（openssl 不保证存在，SslStream 保证存在且直接吃到系统信任
库）。x-core 只定义 `TlsInfo` / `HttpResponse` / `DiagStep` 三个模型，
`NetworkManager` 上新增 `tls_info` / `http_probe` 两个默认不支持的探针方法。

curl 的退出码直接映射退出码体系，不猜：6/7（解析失败/连不上）→ NotFound(3)，
28 → Timeout(6)，35/60（TLS 握手/证书不可信）→ InvalidState(8)，其余 →
System(1)。`-w "%{http_code}|%{time_total}|%{remote_ip}|%{size_download}"`
的统计行解析有个坑：头部里也可能出现“数字+|”的行（如 HTTP 状态行之外的
头值），所以取**最后一个**匹配 `\d|` 的行作统计行起点，而不是第一个。
多次 1xx 前导响应（代理/HTTP2 升格）按 curl 语义以最后一条状态行为准。

## Windows SslStream 脚本：format! 里的括号三连坑

一段 raw string 的 PowerShell 脚本要同时应付 ①format! 的 `{{ }}` 转义、
②PS 语法括号、③DER 字节扫描，实测踩了三次才活：

- **少一个 `}}`**：`foreach($e in $cert.Extensions){…}` 的闭括号在转义串里
  漏写，PowerShell 报“语句块或类型定义中缺少右"}"”——先 `cargo build`，
  再把转义串还原成真实脚本落盘、用 `PSParser::Tokenize` 数括号
  （balance≠0 即没救），比对着源码肉眼数靠谱。
- **`GetString(` 少一个 `)`**：花括号平衡了不等于方法调用括号平衡，
  Tokenize 这次报“方法调用中缺少")””。两种检查都要做。
- **变量名撞车**：主脚本用 `$t` 装 TcpClient，SAN 扫描循环又用 `$t` 装
  DER tag 字节——`$t.Close()` 在数组越界后拿到的是 Byte，抛
  “[System.Byte] 不包含名为 Close 的方法”，catch 往 stdout 追加一行
  `ERR:…`，而 JSON 已经先打出去了；于是 `ConvertTo-Json` 输出变成
  “合法 JSON + 第二行垃圾”，解析报 trailing characters。脚本内所有
  临时变量统一加前缀或换名（`$tg`），且 catch 只写 ERR 前缀不写正文
  多行。

SAN 扫描最初用“找 0x82 字节”的土法，结果把扩展值里碰巧等于 0x82 的字节
当标签，输出 `T?` 这类垃圾名——违反诚实原则。改成正规 DER 走：序列头
`30` + 长度（短式/长式），逐项读 tag/长度，`(tag & 0x1f)==2`（dNSName）
才收，越界截断。输出宁可少不可假。
